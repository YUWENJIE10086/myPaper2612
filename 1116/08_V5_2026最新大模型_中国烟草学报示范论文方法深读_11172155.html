第一，必须分清三类大模型

模型家族真正擅长的任务错误的使用方式
LLM（Qwen3.5等）正式条款、工单文本、问数任务理解及工具调用未经数据库执行便直接生成经营数字

如何读方法章节，而不是只看算法名

  1. 先摘原论文输入变量、样本单位和标签/预测目标，不要从题目推断。
  2. 逐个模型写出它负责哪一步，有没有数学目标及优化损失。
  3. 列实验所比较的业务规则、统计模型及神经模型，分清训练与样本外数据。
  4. 核对论文实际业务效果指标，不能将他人的最优误差直接写成自己预期。
  5. 最后把我们的创新与前人研究问题放在一张表中审查，确认不是模型替换。

Chronos-2、TimesFM-3、TabPFN-3.5是最新基础模型的代表，但在卷烟数据上并没有一个经证实的统一最优方案。研究时应将季节朴素、ARIMA、CatBoost、LightGBM或普通RAG作为充分调优的强基线。TabPFN-3.5权重带非商业许可限制，企业部署必须单独核实。

第四，2026年11月新论文CoCo的核心机制

《TSFM Meets LLM: Context as Covariates》（2026-11-03）针对‘LLM理解文字但数值预测不稳，TSFM数值预测较强却难处理文字’这一明确矛盾，让LLM把新闻、报告和文字事件编码成数值预测协变量及置信度，再以TSFM进行预测。公开论文采用GRPO对齐和TSFM协变量适配，示例包含Qwen3与Chronos-2。这属于近期预印本方法，不表示已经在卷烟营销数据上证明有效。

实验组研究职责想证明什么
E0季节朴素/ARIMA/GBDT成熟数值模型大模型是否真有必要
E1纯Chronos2或TimesFM3预训练数值预测无文本时模型能力
E2时序模型+人工事件有真实事前可用策略事件政策信息本身的新增价值
E3时序模型+LLM原始事件文本抽取未强校验模型是否会错用条款
E4时序模型+可验证LLM事件加入发布时间、适用SKU与来源校验行业新机制是否减少错误
E5有训练资料后GRPO/LoRA奖励/参数高效微调后训练相比单纯提示是否有真实增益
2026年10月的WhatIf-Bench和TSFM因果审计提醒：条件预测可以在从未见过的干预场景下失效，模型的预测差异不能直接解释成策略引发的因果收益。

A｜知识增强的营销时序基础模型

可行性：研究前沿较高，须补政策和日/周SKU数据

研究问题及代表性

政策文本中存在发布时间、生效期和适用品规，数值销量历史不能直接表达；LLM能读文本但不能负责可信数值预测。

具体怎么实现，哪个模型负责什么

Qwen3.5从正式政策提取结构化事件与证据置信度→Chronos-2或TimesFM-3预测分位数→时点与SKU适用规则验证。若有足够配对数据，再尝试LoRA/GRPO对齐。

需要什么数据

0805多规格按日查询和品牌月进货；需新增业务策略文书、正式发布时间/生效日、真实供给和SKU映射。

强基线

季节朴素/ARIMA/GBDT、纯TSFM、TSFM＋人工事件、TSFM＋自由LLM事件、本文可信结构化事件。

逐项实验验证

  1. 同SKU与相同历史窗口做未来1/2/4周MASE、wMAPE、CRPS和80/95%区间覆盖。
  2. 对照人工提取、纯LLM、Qwen结构化抽取，计算条款适用SKU/生效期F1。
  3. 逐个消融事件时点、置信度、条款来源、业务硬约束，观察误差与非法情况。
  4. 跨月份、地区、品牌和新政策类型留出，重点报告失败场景和拒识。
  5. 将模型预测与正式供给约束校验，输出可审查的情景而不自动下发投放。

最终结果怎样落地

品规预测区间+条款证据+政策事件提醒+人工决策参考。

重复与退稿风险：崔建华已有LLM策略辅助；2026 CoCo已经提出文本协变量，不能仅复制它。应新增可消融的政策时点合法性和业务约束，并承认条件预测不是因果干预。

B｜具有指标血缘与双重验证的营销问数智能体

可行性：最推荐：与2608数据契合，落地最清晰

研究问题及代表性

销售、扫码、门店运营多表的主键、粒度、分母不同，普通LLM直接生成SQL会有错连接、重复计数、权限泄漏风险。

具体怎么实现，哪个模型负责什么

Qwen3.5＋Schema/指标字典检索＋受限SQL AST→只读数据库执行→独立校验总量、分母、客户去重及权限→带证据答案或拒识。

需要什么数据

2608月度销售、扫码、店铺运营、客户档案；需建立数据字典及100—300条由业务人员独立确认的问数金标准。

强基线

人工BI、LLM直接SQL、LLM+Schema、普通RAG-SQL、Agent执行反馈、本文双校验。

逐项实验验证

  1. 分单表、JOIN、同比、分档分组、业务口径歧义、越权六类真实问数题。
  2. 执行准确率与最终数字一致率都报告；禁止把SQL文本相似度当结果。
  3. 消融Schema血缘、AST约束、执行后数值核验、权限规则和拒识。
  4. 跨时间、地区Schema变更的留出评测，记录错表和错误分母。
  5. 真实营销人员计时：每问分钟数、修改次数、错答复核成本、隐私阻断。

最终结果怎样落地

县级营销‘问数—执行—验数—口径解释—合规报表’工作台。

重复与退稿风险：2026行业大模型论文已涉及‘智能问数’，创新只能建立在真实指标血缘、可执行双校验、复杂问题和安全性实验上。

C｜TabPFN-3.5的零售客户小样本可信外推

可行性：可从2608起步，但需要可复核未来标签

研究问题及代表性

只有一年客户月度面板时深LSTM容易过拟合；需要检验表格基础模型在稀有门店和跨地市新样本能否优于调优过的CatBoost。

具体怎么实现，哪个模型负责什么

TabPFN-3.5＋客户时间合法特征＋分组概率校准和低可信拒识，与LightGBM/CatBoost强对照。

需要什么数据

2608客户档案、销售、扫码、店铺经营；未来一个月明确的经营变化事件或数据质量人工真值，最好补下一年/其他地市。

强基线

现有档位规则、Logistic、RF、LightGBM、CatBoost、TabPFN-2和TabPFN-3.5。

逐项实验验证

  1. 按客户×月份审计缺失/零值/异常与标签来源。
  2. 按月份滚动测试并独立留新客户，不能随机拆分同一客户的月份。
  3. 比较PR-AUC、Recall@K、Brier、推理成本与稀有业态误报。
  4. 消融采集缺失特征、分组概率校准、风险拒识；保持相同基线。
  5. 跨区县/次年检验最差群体和新客户错误；模型许可与生产用途分离。

最终结果怎样落地

客户经理可人工复核的经营波动或采集异常清单。

重复与退稿风险：只把官方档位交给TabPFN预测，创新仍然很弱。非商业模型权重需审查企业生产部署许可。

D｜LLM与形式方法协同的营销规则编译

可行性：技术成熟与执行价值高，须正式规则授权

研究问题及代表性

货源策略规则跨版本、生效期、区域和档位；LLM说得通并不等于执行合法。

具体怎么实现，哪个模型负责什么

Qwen3.5＋版本化RAG→Policy-DSL候选→SMT/Z3检查数量上界、时点和冲突→人工审批。

需要什么数据

授权的多版次规则文书、条款ID、生效日期、审批单、人工标注DSL与故意冲突的测试样例。

强基线

人工审查、纯LLM、RAG问答、RAG+DSL、RAG+DSL+SMT。

逐项实验验证

  1. 双专家标注规则字段/适用范围及来源文号。
  2. 测试旧版条款、超限数量、错误区域、互斥档位和缺附件。
  3. 消融版本过滤、DSL、SMT、拒识，比较硬约束漏检/误拒。
  4. 跨新版本、新地区和规则异常类型留出。
  5. 真实审核耗时和需要人工修改的次数，以及越权操作阻断率。

最终结果怎样落地

正式策略条款上传—结构化解析—规则冲突提示—人工审批组件。

重复与退稿风险：普通规则问答已重复，只有硬约束准确率、可追溯和正式业务运行对照能体现新贡献。

  3. 用强统计基线和原有流程规则公平对照；不能故意选弱基线。
  4. 每个新机制都必须有消融及失败案例。
  5. 跨品规、地市、月份或规则新版本留出，报告最差群体。
  6. 模型产出必须能进入实际营销统计、规则审核或客户数据质量复核流程。
  7. 记录显存、时延、许可证及内部客户/规则数据保密措施。
  8. 与已发表论文明确区分任务、数据、方法增量和实际管理价值。

第一步先做B方向——可验证营销问数智能体。它能利用2608多表数据和真实业务问数构建任务金标准，具有强实验可测性和管理落地性。第二步核验0805 SKU数据是否有足够真实日/周时间序列，以及能否获得正式政策事件；满足条件后做A方向的LLM+TSFM方法。第三步将TabPFN-3.5仅作客户月表格任务的强基线，不应在没有独立风险标签时强行开题。

七、补充：从最新模型论文到可复现实验的九步操作规程

这里补的是正式科研所需的操作条件，而不是继续堆算法名。每一步需要有可保存的表格、程序日志或业务记录。在数据没有经过核验之前，所有示例只是研究设计，不能在摘要中写成已验证结果。

1. S0 原始业务事实审计

先在受控环境逐sheet读取2608销售、扫码、门店运营以及0805品规记录，输出字段、主键、时间、行粒度、空值/零值和敏感级别。这个阶段决定‘能不能写’，不能提前使用模型拟合结果反推样本纳排标准。

2. S1 科学问题预注册

先写目标：预测某SKU下一周购进量、回答某项经过权限授权的经营问题、校验一条规则是否冲突、或识别下一月经营指标异常。定义一张表或一条数据到底代表什么，冻结主要结果指标和真正需要验证的业务问题。

3. S2 先跑最强简单基线

预测类至少包括Naive/季节朴素、ARIMA及LightGBM；表格类包括Logistic、CatBoost、LightGBM；问数类包括人工BI、纯LLM、Schema+LLM、HybridRAG+LLM。强基线要公平调参，不应故意挑选较弱版本。

4. S3 预训练基础模型验证

Chronos-2/TimesFM-3先用完全零样本预测，再比较相同历史窗口与同样外生变量；TabPFN3.5先当未经领域微调的表格模型，观察不同月份/小样本下是否优于树模型。任务不适合时允许放弃大模型。

5. S4 加入一项真正必要的机制

对A方案只加已批准政策文本事件及可信生效时点；B方案只加跨表指标血缘与SQL执行双校验；C方案只加缺失机制、时间校准与拒识。新增机制需要单独的实验组，否则不能说清‘创新来自哪里’。

6. S5 时间与群体外推

时间预测必须采用滚动历史/样本外窗口，问数用全新口径问题、未知的字段组合和跨区县别名，规则用历史未见的版本。结果必须列训练集、验证集、测试集数量，禁止挑选测试集最优版本。

7. S6 消融与对抗压力

去掉每个新组件，注入漏扫码、错主键、模糊日期、政策条款缺页、非法SQL、规则版本冲突。只有同时提升性能且降低有业务意义的错误，才可能形成学报可接受的技术贡献。

8. S7 业务回放与现场记录

输出真实可复核的业务对象：营销问数准确报表、SKU预测区间、策略条款冲突、客户数据核查工单。没有真实上线记录，所有节省时间、改善效率必须限定为离线实验/模拟。

9. S8 模型许可、安全与投稿预审

记录模型权重版本、许可、显存、每次推理时间、总Token、人工复核次数、非法输入阻断率；公开仓库只保留匿名聚合数据和代码，内部策略原文与门店身份不得未经批准上传。

八、关键模型的输入、指标和失败机制

模块最小数据格式与实现方法必须说明的适用边界
预测模型：训练数据格式记录必须按 SKU_id、area_id、date、target_actual、history_available、policy_published_at、policy_effective_at、policy_scope、stock_or_allocation_cap 的概念组织。最后几列需从系统核验，缺失不能伪造。预测SKU下一周时，只允许当时已经发布并确定生效的外生变量。若只有品牌月汇总的19个观测点，不能默认满足Chronos2/TimesFM3高质量跨场景验证，更不能强行训练GRPO。
预测模型：损失与校准可以使用Pinball分位数损失Lτ(y,q)=max(τ(y−q),(τ−1)(y−q))，并在真实测试中观察CRPS、区间覆盖和宽度；置信门控只是待检验机制，不属于已证明有效的结论。强基线需要同分位数目标或正确的概率指标。不能简单对每个品牌计算普通MAPE（大量零值会不稳定），优先报告MASE、加权wMAPE和异常时段误差。
Text-to-SQL：主键和口径测试真实测试题示例：‘统计2025年10月各业态有效采集客户占比，并标明分母是所有客户还是上线客户。’这类题同时检验业态字段、客户去重、有效采集定义、时点和分母。问题无法由现有表回答时应解释不可计算，而不是补造答案。必须有业务人员审核的真实SQL与结果，不能只用大模型生成的数据问题再让同一模型评测。
Text-to-SQL：安全限制所有模型生成的SQL先形成受控AST：允许SELECT、固定表视图、限定时间/行数、限制敏感字段、拒绝写操作及注入；只读执行后再从另一条独立聚合途径复核合计。生成查询失败后的重试次数要有限制。论文以执行准确率与最终数值一致率为第一指标，同时报告正确拒识率、越权阻断和人工核验分钟数。
表格基础模型：正确验证客户i在2025年某月t的输入只能使用t及之前已生成的历史特征，不允许年底统计的‘全年客户方差’泄漏到前几个月。客户跨月份同时出现于训练和测试只适用于既有客户未来预测；新客户泛化必须另做按客户留出。TabPFN3.5公开基准成绩不能代替本地泛化；如果CatBoost更强，应如实保留并转向分析小样本/模型适用边界。
规则编译：形式约束构造通用规则记录（规则编号、批准日期、生效起止、地区、SKU、客户档位、数量上限、例外条件、条款来源）。LLM抽取后用Schema查类型和必填，SMT求解检查配置规则之间有没有逻辑冲突，冲突则返回可核查的原条款片段。不能将大模型‘解释理由通顺’当作规则没有冲突的证据，硬约束漏检才是关键失败指标。

十、正式论文怎么写出真正的方法创新

论文正文切忌在2.1节介绍Qwen、2.2节介绍Chronos、2.3节介绍RAG，然后在3.1节只贴一个预测准确率。正确写法是在引言明确一个可以被证伪的业务机制，例如‘营销政策事件是否能在预测时点以可信方式提供额外信息’，然后方法章节把政策时点与适用范围数学化，实验章节分别对比手工事件、未校验LLM事件和可信事件，结果章节汇报预测误差、条款错误和业务可执行性三个层面的证据。

如果要写营销问数智能体，技术创新不能是‘让AI理解Excel’。要定义指标血缘与统计不变量：JOIN后多出来的重复行是怎样发现的，客户去重是怎样验证的，同比与环比何时不适用，业务口径无法确定时怎样拒识。只有能让错误答案减少并能解释错误为何发生，才有接近成熟信息类研究论文的论证闭环。

论文结果的每一张表必须能回溯到一次固定数据版本的实验：表1样本情况、表2基线指标、表3主方法提升、表4组件消融、表5跨时间/地市外推、表6业务操作时间与安全结果。测试集在设计冻结后只能用于最终报告，不因结果不漂亮临时修改主要指标。

研究边界：基础模型的条件预测不是合法识别的政策因果效应；已经发表或公开的技术报告也不意味着烟草营销场景已经证明适用。企业敏感数据与模型权重许可必须提前审查。
